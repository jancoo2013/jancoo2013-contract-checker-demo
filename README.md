# AI-аудит договора аренды на иврите — закрытый MVP

Русскоязычный прототип для предварительного анализа **текстового** договора аренды жилья на иврите.

## Что делает текущая версия

Текущий вертикальный срез работает только с готовым текстом договора:

1. Пользователь вставляет полный текст договора на иврите.
2. Приложение детерминированно удаляет персональные данные.
3. Обезличенный текст показывается пользователю перед отправкой.
4. Валидатор проверяет, достаточно ли текста договора для AI-анализа.
5. OpenAI вызывается через BYOK API-ключ закрытого теста.
6. Ответ запрашивается как Structured Output по строгой схеме.
7. После ответа выполняется детерминированная проверка цитат: каждый риск должен ссылаться на дословную цитату из обезличенного текста.
8. Отчёт отображается на русском языке.

## Важно: текст, не фото

Этот MVP **не распознаёт фотографии** и **не запускает OCR**. Старые OCR-заготовки в репозитории считаются устаревшими и не используются в основном пользовательском сценарии.

## Обезличивание перед OpenAI

Перед отправкой в OpenAI приложение удаляет типовые персональные данные:

- имена и роли сторон в личных полях;
- израильские ID;
- телефоны;
- email;
- адреса;
- банковские реквизиты.

Цель продукта — анализировать **условия договора**, а не личности сторон. Валидатор не требует имён, номеров ID, телефонов, адресов или подписей для признания текста пригодным к AI-анализу.

## BYOK API-ключ

Поле OpenAI API-ключа — временный механизм **Bring Your Own Key** для закрытого тестирования.

- Ключ не хранится в GitHub.
- Ключ не должен добавляться в код или README.
- Приложение не выводит ключ в ошибки или отчёты.
- Договорный текст не нужно держать в сессии дольше необходимого; используйте кнопку очистки после теста.

## Structured Outputs и фактическая корректность

Structured Outputs помогают получить ответ в ожидаемой JSON/Pydantic-форме. Это гарантирует форму данных, но **не гарантирует фактическую правильность юридических выводов**.

Поэтому после модели применяется отдельная проверка доказательств:

- цитаты рисков должны дословно существовать в обезличенном источнике;
- неподтверждённые риски удаляются из отображаемого результата;
- неподтверждённые пункты понижаются до `unclear`;
- предупреждения показываются отдельно.

## Юридический дисклеймер

Это прототип для предварительного анализа и подготовки вопросов. Он **не является юридической консультацией** и не заменяет проверку адвоката, особенно при красных рисках, крупных суммах или нестандартных условиях.

## Локальный запуск

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

## Проверки

```bash
python -m py_compile app.py contract_checker/*.py
python -m unittest discover -s tests
```

## Ручной сценарий тестирования

1. Запустить `streamlit run app.py`.
2. Вставить полный текст договора аренды на иврите.
3. Нажать **«Обезличить и проверить»**.
4. Проверить раскрытый блок с обезличенным текстом.
5. Убедиться, что статус валидации успешный.
6. Ввести тестовый OpenAI API-ключ BYOK.
7. Выбрать модель, по умолчанию `gpt-5.4-mini`, или указать ручной model ID в advanced settings.
8. Нажать **«Запустить анализ»**.
9. Проверить вердикт, красные/жёлтые риски, обычные пункты, неясные фрагменты, вопросы и предлагаемые изменения.
10. Открыть advanced JSON только при необходимости отладки.
11. Нажать **«Очистить договор и ключ»** после теста.

## Оставшиеся ограничения

- Нет OCR и обработки изображений в текущем MVP.
- Нет реального юридического заключения.
- Детерминированное обезличивание консервативное и может не покрыть все редкие форматы PII.
- Проверка цитат снижает риск неподтверждённых выводов, но не доказывает юридическую правильность интерпретации.
- Качество анализа зависит от полноты вставленного текста и выбранной модели OpenAI.
